# 面试追问 Q&A 清单（辉瑞 AI Pilot · GLP-1 × AI 医药研发项目）

> 回答公式：**一句话结论 → 数据/方法 → 业务含义**。红线：仿真部分全部标注 `is_simulated`，任何问题不回避数据真实性；AI Pilot 是"研发场景 + 深度学习工程师"定位，回答重心放在**模型原理与研发业务价值**上。

---

## 一、动机与背景（辉瑞 / AI Pilot）

**Q1. 为什么投辉瑞 AI Pilot，而不是商业分析岗？**
→ 辉瑞 CRDC 是 I-IV 期临床试验设计、数据管理与生物统计的核心枢纽（公司介绍原文），AI Pilot 恰好是我想要的交叉点：**AI 直接嵌入研发决策链**（试验设计/成功率预测/安全评估），比商业分析更前端、更硬核；我的项目就是照这个场景做的。→ 加分：提一句辉瑞研发管线（如 GLP-1 口服制剂、肿瘤 ADC），表示做过功课。

**Q2. 你项目里"AI 落地 0→1"具体指什么？**
→ 0=裸数据，1=可复现、可解释、可汇报的完整闭环：数据接入（真实 API）→ 特征工程 → 建模（LR/RF/手写 MLP）→ 严格评估（训练集内 5 折 CV 调参 + 独立分层 holdout 最终验证 + 平局校正 AUC）→ 统计设计（样本量）→ 自动化简报。每一步有产出物，`python src/run_pipeline.py` 一键复现——这就是跨国药企里 AI 项目从想法到可交付的形态。

## 二、深度学习（核心追问区，深度学习工程师定位）

**Q3. 你的手写 MLP 反向传播怎么推的？**
→ 结构：输入层(8) → tanh 隐藏层(8) → 单个 sigmoid 输出（二分类）。推导：损失 BCE，对输出层 δ_out = (p−y)/n；隐藏层 δ_hidden = (δ_out·W2ᵀ)⊙(1−tanh²)；梯度 W1=Xᵀ·δ_hidden，W2=hᵀ·δ_out，SGD 更新。→ 加分：说出"为什么要除 n"（梯度期望的批量近似）和"为什么用 tanh"（中心化、梯度比 sigmoid 稍稳）。

**Q4. 手写 MLP 和 sklearn 的 MLPClassifier 比，你担心什么差异？**
→ 我的实现：无 bias 正则、无自适应学习率、无 mini-batch shuffle、epochs 固定——因此和 sklearn 对比（AUC 0.820 vs 0.820）只能证明**实现正确**，不能证明"最优"。→ 诚实加分点：面试官最怕"只会调包"，手写 + 自知局限反而建立信任。

**Q5. 你的数据只有 730 条，深度学习的价值在哪？**
→ 坦白：730 条只够"演示深度模型可运行"，真正的价值是**数据量不足时的工程取舍意识**（用简单模型做基线、手写 MLP 验证梯度正确性）；如果换大规模数据（如真实 EHR/影像/基因组），同样架构可直接扩展。→ 顺势说清过拟合手段：L2、dropout（我的实现可加）、早停、数据增强（对表格数据用扰动/合成）。

**Q6. 类别不平衡怎么处理？你数据平衡吗？**
→ 我的数据 380/350 基本平衡；若不平衡：AUC 天然对不平衡鲁棒（这正是我用 AUC 主指标的原因）、可用 class_weight、SMOTE、或改用 PR-AUC。→ 追问防住：能说出 ROC-AUC 对不平衡的"乐观偏差"场景（负样本极多时 AUC 虚高，此时看 PR-AUC）。

## 三、机器学习与评估

**Q7. AUC 怎么实现的？为什么不用 accuracy？**
→ 手写 Mann-Whitney 秩和（含平局平均秩校正）：AUC = (正样本秩和 − n₁(n₁+1)/2)/(n₁n₀)，等价于随机正样本排在随机负样本前面的概率；accuracy 对阈值敏感，AUC 与阈值无关。→ 加分：能画出 ROC 并解释"越靠近左上越好、随机=0.5 对角线"。

**Q8. 三个模型怎么选？AUC 用哪个口径？**
→ 以**独立 holdout AUC** 为准（初版 CV 里的特征含目标泄露、AUC 虚高，已修复），再综合三个维度：AUC、可解释性（LR 系数可读）、鲁棒性（5 折方差）。业务场景"试验成功率预测"要跟研发团队讲清为什么，所以**主推 LR/RF + 特征重要性**，MLP 作为"深度学习能力证明"；生产环境会再做 Calibration（Platt/Isotonic）和阈值选择。

**Q9. 特征重要性怎么解读？有什么陷阱？**
→ 解读：申办方（sponsor_lilly/sponsor_novo）与试验完成率相关（研发体系成熟），肥胖适应症完成率偏低（招募难/停药率高——符合领域常识）；具体数值以最新 run 的特征重要性输出为准（LR 系数与 RF importances 双口径）。陷阱：**相关 ≠ 因果**（申办方规模与试验质量混淆）、特征共线性、小样本下重要性不稳定——所以结论只做"探索性信号"，不下因果断言。

## 四、统计与试验设计（CRDC 生物统计方向）

**Q10. 样本量公式推导一下（二分类）。**
→ 两组率 p1/p2，检验统计量近似正态：n = [z_α·√(2p̄(1−p̄)) + z_β·√(p1(1−p1)+p2(1−p2))]²/(p2−p1)²，α=0.05 双侧 z=1.96、功效 80% z=0.84。→ 能说出假设：正态近似、方差合并 vs 不合并、以及实际还要加 10-20% dropout 余量。

**Q11. 为什么真实试验样本量比我算的大得多？**
→ 我算的是"单终点、单次检验、无期中分析的理想情况"；真实试验要考虑：主要终点往往是连续变量且效应量更小、多重终点/亚组要多重性校正（α 分配）、期中分析 α 消耗（O'Brien-Fleming）、入组脱落与依从性、非劣效/等效设计需更大样本——所以 SURMOUNT-1 动辄 2500+ 例。→ 这是"知道理想公式 + 懂现实工程"的分水岭问题。

**Q12. 假设检验的局限？p 值能说"概率"吗？**
→ p 值 = 原假设下出现当前及更极端结果的概率，**不是**"结论为真的概率"；用 95% CI 补足效应量信息（bootstrap CI 我项目里已实现）；报告效应量和置信区间比只报 p 值更完整。→ 加分：提到 FDA 对终点选择、多重性、缺失数据的监管要求（GCP/ICH E9）。

## 五、数据与安全处理（CRDC 职能）

**Q13. FAERS 不良事件数据你怎么处理的？有什么坑？**
→ 结构：每报告含多个 reaction 术语，我先按 MEDDRA 顶层分组聚合（GI/恶心呕吐/体重下降/注射部位），再算严重率；坑：FAERS 是自发报告（报告偏倚、重复报告、无分母——**不能直接算发生率**），只能做信号方向监测；生产环境应做去重（case id）、按人年归一。→ 记住：这是药物警戒（PV）部门日常，说到"信号检测"即加分。

**Q14. GCP / 数据管理意识体现在哪？**
→ 我项目里：数据来源可追溯、仿真数据显式标注、SQL 数仓保证口径统一、pipeline 可复现（CI 可加）；对应到 CRDC 就是 GCP 的数据完整性与可审计性（ALCOA+：可归因、可追溯、同步、原始、准确）。→ 表明知道"研发数据 ≠ 互联网数据"的合规约束。

## 六、开放题（展示思考深度）

**Q15. 给你 4 个月，你会怎么把"临床试验结果预测"做深？**
→ 三阶段：① 数据：全领域拉取（不止 GLP-1）到万级，加试验时长/设计（双盲、多中心）/终点类型/地理特征；② 建模：加 XGBoost/LightGBM 基线 + 时间维度的序列模型（试验设计变化趋势），报告 Calibration 与阈值决策曲线；③ 业务：与医学/统计团队对齐"预测什么"（成功完成？达到主要终点？提前终止？）——**先定义业务问题，再谈模型**。

**Q16. 用一句话总结这个项目最难的地方。**
参考：**在 730 条真实数据的约束下，同时做到"方法严谨（含数据泄露修复）、深度学习有真实实现、结论诚实"三件事**——这也是 AI 落地医药研发的常态：数据永远不够，但决策不能停。

## 七、数据泄露与标签定义（打磨后新增，面试高频）

**Q17. 你的特征里会不会有数据泄露？怎么防的？**
→ 会——初版我把 `is_active_status`（由 status 直接派生）和 `estimated_completion_year` 当特征，而标签正是 `status=="COMPLETED"`，等于"用答案猜答案"，CV AUC 虚高（~0.88）。修复：① 删除这两个特征，只保留试验设计类特征（分期/适应症/入组规模/设计文本等）；② 评估改为"训练集内 5 折 CV 调参 + 独立分层 holdout 最终验证"，holdout 全程不参与调参，避免选择偏差；③ 加回归测试 `tests/test_pipeline.py::TestNoLeakageFeatures`，特征集里再出现泄露特征直接 CI 失败。→ 加分：主动说出"标准化统计量也只从训练集估计"——scaler 泄露是同类问题，面试官常连环追问。

**Q18. status==COMPLETED 就等于"试验成功"吗？你的标签定义经得起推敲吗？**
→ 经不起，诚实说：Completed 只代表"按计划走完"，不代表达到主要终点；Terminated 也可能是因疗效太好提前终止。所以这个标签是"可得数据的近似"，我用它演示方法，但业务上真正的目标应是"达到主要终点/获批"。→ 进阶答案：这正是 Q15"先定义业务问题再谈模型"的体现——真实落地时会与医学/统计团队对齐标签口径，并考虑用终点结果、提前终止原因、监管结局（获批/失败）做更细的标签。
